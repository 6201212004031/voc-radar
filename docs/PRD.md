## 一、产品目标

### 1.1 原型要实现什么

构建一条**自动化评论分析流水线**，将跨境卖家面对的"上千条竞品评论"转化为**可执行的产品改进方向和差异化卖点建议**。核心是把"采集 → 预处理 → 聚类 → 分级 → 归因 → 建议 → 报告"串成一条自动化链路，区别于 ChatGPT 手动多轮交互。

### 1.2 比赛 Demo 要展示的效果

5 分钟路演中，评委通过**交互式决策看板**一眼看到：

| 展示目标 | 评委感知 |
|---------|---------|
| 一键输入品类 → 10 分钟出报告 | 自动化 pipeline 的效率价值 |
| 痛点热力图（影响面量化） | 数据驱动的洞察深度 |
| 点击痛点下钻看根因归因（qwen3.7-max）+ 评论原文证据 | 证据驱动、可追溯的 AI 推理 |
| 改进优先级四象限矩阵 | 闭环到可执行动作 |
| 竞品共性弱点 → Listing 卖点建议 | 从分析到商业决策的闭环 |

**Demo 即产品**——看板必须做到"打开就懂、点击就下钻、结果一目了然"，不依赖口头解释。

### 1.3 诚实边界

- VOC Radar 提供**产品改进和差异化方向的参考信号**，不做"选品决策"
- AI 根因归因是**辅助参考**，最终决策仍需卖家判断
- 原型阶段数据来源为公开数据集，生产级数据采集为复赛/后续规划

## 三、需求池

### 分级原则

- **P0**：原型必须实现的核心功能（初赛加分项，缺一不可演示）
- **P1**：时间允许应该实现（增强 Demo 效果和评审维度覆盖）
- **P2**：复赛阶段再做（初赛不实现，写入路线图即可）

### 3.1 P0 — 原型必须实现

| ID | 功能 | 描述 | 验收标准 |
|----|------|------|---------|
| P0-1 | 评论数据加载 | 支持从 Kaggle Amazon Review 数据集加载评论；**用户显式指定竞品 ASIN 时按 ASIN 过滤**（全部未命中时报错提示，不静默回退全量；部分命中时忽略缺失并记录日志） | 能加载至少 3 个竞品共 500+ 条评论到 SQLite |
| P0-2 | 评论预处理 | 去重、过滤非 VP 评论、元数据提取（星级/日期/变体/点赞数/是否有图） | 预处理后评论结构化存储，含元数据字段 |
| P0-3 | 语义聚类 | text-embedding-v4 向量化差评 + scikit-learn 聚类，得到 8-15 个痛点簇 | 聚类结果可解释，每簇有 Top 5-10 代表性评论 |
| P0-4 | 痛点标签生成 | qwen3.7-max 为每个簇生成痛点标签 + 影响面统计 | 每个痛点簇有简洁标签 + 评论占比/平均星级 |
| P0-5 | 根因归因 | 对 Top 5 痛点调用 **qwen3.7-max**（主力模型，经全样本对照实验选定；DeepSeek-R1 为可选补充通道，由 `ATTRIBUTION_MODEL` 配置切换），输出根因 + 证据引用 | 每条结论引用评论原文，无证据时明确说明"无法确认" |
| P0-6 | 改进建议生成 | qwen3.7-max 整合归因结果，输出结构化改进卡片 | 每个痛点有：根因→改进措施→成本标注→优先级 |
| P0-7 | 交互式决策看板 | 单页 HTML + Chart.js：痛点热力图、优先级矩阵、点击下钻 | 打开即懂，点击痛点可看归因链路和原文证据 |
| P0-8 | 报告导出 | 导出 Markdown 格式结构化报告 | 一键导出包含全部洞察的 MD 报告 |

### 3.2 P1 — 时间允许应实现

| ID | 功能 | 描述 | 备注 |
|----|------|------|------|
| P1-1 | 痛点分级机制 | 区分"需要根因推理的痛点"（体验型/环境触发型）和"只需归类的痛点"（简单事实型），深度归因只用于前者 | 控制成本 + 叙事亮点"知道什么时候该用推理" |
| P1-2 | 图片缺陷识别 | qwen3-vl-plus 识别带图差评中的买家秀物理缺陷 | 增强多模态评审维度 |
| P1-3 | 差异化卖点建议 | 分析竞品共性弱点 → 你的 Listing 应强调的卖点 | 闭环到商业动作，强化业务价值维度 |
| P1-4 | 时间趋势分析 | 痛点随时间的趋势（是否在改善/恶化） | 增强数据深度 |
| P1-5 | PDF 报告导出 | 在 Markdown 基础上增加 PDF 导出 | 路演材料更专业 |
| P1-6 | 归因模型对比实验（✅ 已完成，2026-08-29） | 同一 Top 5 痛点全样本分别用 qwen3.7-max 与 DeepSeek-R1 归因对照 | 结论：qwen3.7-max 5/5 综合占优且平均耗时约为 R1 的 1/2.4，据此切换为主力模型（此即 v1.1 的 P0-5 变更依据） |

### 3.3 P2 — 复赛阶段再做

| ID | 功能 | 描述 |
|----|------|------|
| P2-1 | Rainforest API 集成 | 通过 ASIN 自动获取结构化评论（免费额度 100 次/月） |
| P2-2 | 刷评自动识别 | qwen3.5-flash 初判模板化刷评并标记可疑 |
| P2-3 | 持续监控 | 定期跟踪竞品评论变化，推送新增痛点 |
| P2-4 | 多品类对比 | 跨品类痛点 benchmark |
| P2-5 | 用户账号系统 | 多用户、项目保存、历史报告 |
| P2-6 | 云部署 | 从本地运行升级到云端部署 |

### 4.3 交互方式

| 交互 | 行为 |
|------|------|
| 输入品类/ASIN | 触发完整 pipeline，显示进度条（评论入库→聚类→归因→生成报告）；ASIN 输入将触发竞品过滤 |
| 点击痛点条 | 下钻到痛点详情面板（弹窗或右侧抽屉） |
| 点击"查看原文" | 滚动到代表性评论区并高亮对应评论 |
| 点击"查看买家秀图片" | 弹出图片灯箱，显示 qwen3-vl-plus 识别的缺陷标注 |
| 悬停四象限散点 | 显示痛点名称和关键指标 tooltip |
| 点击"导出报告" | 下载 Markdown（P0）/ PDF（P1） |

### 4.4 视觉风格

- 配色：深色主题（科技感），痛点用红/橙/黄渐变表示严重程度
- 字体：无衬线，数据用等宽字体
- 关键数据用大字号 + 高对比色突出
- 路演友好：截图即懂，无需口头解释每个元素

## 七、v1.1 变更记录（2026-08-29）

### 7.1 归因主力模型切换：DeepSeek-R1 → qwen3.7-max

**变更**：P0-5 根因归因的主力模型由 DeepSeek-R1 切换为 qwen3.7-max；R1 降级为可选补充通道，由后端 `settings.ATTRIBUTION_MODEL` 配置切换，不再作为默认。

**实验依据**（2026-08-29，Top 5 痛点全样本对照实验，见 `backend/compare_r1_qwen.py`）：
- 归因质量：qwen3.7-max 在 5/5 个痛点上综合优于 DeepSeek-R1（证据引用准确度、根因具体度、可执行性）
- 效率：qwen3.7-max 平均耗时约为 R1 的 1/2.4
- 适用边界：R1 在长链路推理任务上仍有理论优势，保留为补充通道以应对复杂归因场景

**同步修正范围**：前端进度条/详情面板/KPI 文案、后端 SSE 阶段描述与报告模板（`s7_report.py`）、Demo 种子数据（`seed_demo.py`）、本 PRD 共 13 处 R1 表述。KPI 口径同步修正：`attribution_count` 由"Top5 标记数"改为"Attribution 表实际归因记录数"（旧名 `r1_attribution_count` 保留为兼容别名）。

### 7.2 新增：竞品 ASIN 过滤（P0-1 细化）

原型的品类关键词仅标注分析场景（数据范围为内置 Kaggle 数据集全量）；用户显式输入竞品 ASIN 时，S1 阶段按 ASIN 真实过滤评论。**全部 ASIN 未命中数据集时明确报错**（不静默回退全量），部分命中时忽略缺失 ASIN 并记录日志。实现位于 `s1_ingest.py` 的 `_apply_asin_filter`，过滤标记 `config.asins_user_specified` 在创建项目时写入。
